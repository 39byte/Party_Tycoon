# 노션 '진행 중' 항목 처리 (Party_Taikun 전용)

## 고정 정보

- 데이터소스: `collection://41322e7d-019b-8089-8a69-000bf0822fdf` ("수정 목록")
- 상위 페이지: `40922e7d019b80258fefde5a393623a2` ("정당 키우기 메모")
- 속성: `이름`(제목), `상태`(시작 전 / 진행 중 / 완료), `폼펙터`(PC / 모바일), `체크 표시됨`(체크박스)
- 이 스킬은 **`상태`만** 기준으로 한다. `체크 표시됨`은 무시한다.

## 절차

1. **조회**: `notion-query-data-sources`(SQL 모드)로 조회한다.
   `SELECT url, "이름", "폼펙터" FROM "collection://41322e7d-019b-8089-8a69-000bf0822fdf" WHERE "상태" = ?` with `params: ["진행 중"]`
   한글 컬럼명은 큰따옴표로 감싼다.
2. **선택**: 0개면 "진행 중 항목 없음"을 알리고 끝낸다. 1개 이상이면 목록을 보여주고 `AskUserQuestion`으로 처리할 항목을 고르게 한다. 고르지 않은 항목은 건드리지 않는다.
3. **상세 확인**: 선택한 페이지를 `notion-fetch`로 열어 본문 설명까지 읽는다. 제목이 "→"로 끝나는 등 문장이 미완성이면 해석을 사용자에게 확인한다.
4. **구현**: 프로젝트 구조는 `index.html`(화면·상태), `logic.js`(순수 규칙), `art.js`(SVG)다. 빌드·외부 라이브러리가 없다. UI 작업이면 `game-ui-frontend` 스킬 기준을 따른다. `폼펙터`가 `모바일`이면 모바일 레이아웃(좁은 화면, 16px 여백 등)을 확인한다.
5. **테스트**: 규칙(`logic.js`)을 바꿨으면 `node test.js`를 실행한다. 실패하면 **중단하고 실패 출력을 보고한다.** 노션 상태는 바꾸지 않는다.
6. **커밋/푸시**: 항목마다 별도 커밋한다. 병행 세션이 `index.html`에 미커밋 변경을 둘 수 있으므로 `git diff`로 본인 변경분만 stage한다. 커밋 메시지는 최근 스타일(`feat:` / `balance:` 등 + 한글 설명)을 따른다. 그 뒤 `git push origin main`을 실행한다.
7. **노션 완료 처리**: `notion-update-page`(`command: update_properties`)로 해당 페이지의 `상태`를 `완료`로 바꾼다. `폼펙터`가 비어 있고 제목에 "모바일"이 들어 있으면 `모바일`도 채운다.
8. **보고**: 항목별로 변경 요약, 커밋 해시, 노션 상태 변경 여부를 한국어로 짧게 정리한다.

## 주의

- 구현이 막히면 노션 상태를 바꾸지 않고 막힌 이유만 보고한다.
- 여러 항목을 고르면 한 항목씩 순서대로 처리하고, 항목마다 커밋·완료 처리를 나눈다.
- 완료 처리 후에는 `notion-query-data-sources`로 다시 조회해 상태가 바뀌었는지 확인한다.
