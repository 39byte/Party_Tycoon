# Game UI Frontend (Party Tycoon 적용판)

목표: 범용 대시보드가 아니라, 게임 세계관(한국 정치 시뮬레이션)에 어울리고 읽기 쉬운 UI.

## 프로젝트 전제

- 단일 `index.html` + `logic.js` + `art.js`. **빌드·외부 라이브러리 없음**, 휴대폰 지원 필수.
- 지도/인물/장면은 `art.js`의 SVG, 텍스트 위주 UI는 DOM. (캔버스에 텍스트 UI를 넣지 않는다.)
- 테마는 `index.html`의 CSS 변수(`--bg`, `--fg`, `--accent`, `--hud`, `--on-hud`, `--ok`, `--danger`, `--gold` 등)를 재사용한다. 새 색은 변수로 추가하고 하드코딩하지 않는다.
- 순수 규칙은 `logic.js`, 화면/상태는 `index.html`. UI 작업이 규칙을 바꾸면 `node test.js`로 확인.

## 기준

1. 코딩 전에 시각 방향 확인: 분위기, 재질감, 타이포, 팔레트, 모션 톤. 기존 화면과 일관되게.
2. 위계: 핵심 정보(자금·지지율·행동력·다음 선거) → 보조 도구 → 드물게 쓰는 설정(메뉴/서랍 뒤).
3. 첫 화면에서 바로 플레이 가능해 보일 것. 상시 표시 HUD는 한 묶음 + 작은 보조 한 묶음까지.
4. 긴 설명·로어·컨트롤 목록은 서랍/토글/일시정지 화면 뒤로. 상황별 힌트와 일시적 안내를 상시 박스 패널보다 우선.
5. 움직이는 요소(지도, 애니메이션) 위 오버레이는 배경 패널·대비·테두리로 가독성 확보.
6. 데스크톱과 모바일을 처음부터 같이 설계. 모바일은 좁은 스택/칩으로 접는다.
7. 포인터·키보드(`Space` 턴 종료 등)·상태 피드백이 분명할 것. 모달이 열려 있으면 뒤 화면의 입력을 막는다.

## 모션

- 의미 있는 전환 몇 개만 (상태 변화, 보상, 위험, 온보딩). 상시 마이크로 애니메이션 금지.
- `prefers-reduced-motion`을 존중한다.

## 좋은 UI

- 메뉴가 SaaS 관리자 패널이 아니라 게임 안의 물건처럼 느껴진다.
- 브레이크포인트마다 레이아웃이 깨끗하게 적응한다.
- 스크린샷을 찍으면 UI 시안이 아니라 게임 장면으로 읽힌다.

## 안티패턴

- 범용 앱 대시보드 레이아웃, 테마 없는 플랫 스타일, 의도 없는 기본 폰트
- 모든 가장자리에 같은 비중의 박스 패널을 흩뿌리기
- 첫 화면에서 모든 정보(설명·목표·로어)를 한꺼번에 펼치기
- 요소마다 과한 모션
- DOM이 더 명확한데 SVG/캔버스에 텍스트 UI를 넣기
- 모달 뒤 입력이 살아 있는 상태

## 요청/리뷰 시 체크할 것

게임 판타지, 시점, 플레이어 동작(행동), HUD 층위, 모션 톤, 데스크톱/모바일 기대치, 플레이 영역 보호 방식, 피할 안티패턴.
